# debojit10.github.io

Personal site for **Debojit Nath**, ML Engineer — [debojit10.github.io](https://debojit10.github.io)

A single-page portfolio, built as a static Jekyll site and served by GitHub
Pages. No framework, no bundler, no runtime dependencies, no third-party
requests.

---

## Why it's built this way

The site is **three source languages and no build tooling**: Liquid templates,
one hand-written CSS file, one dependency-free JS file. Content lives in YAML
under [`_data/`](_data/); GitHub Pages runs Jekyll on push and publishes the
result.

| | |
|---|---|
| **No `node_modules`** | Nothing to install, nothing to audit, nothing to break in two years. |
| **No Sass** | Custom properties do everything variables-and-nesting used to. The CSS that ships is the CSS in the repo. |
| **No JS libraries** | ~4 KB of vanilla JavaScript. The page is fully readable and navigable with JavaScript disabled. |
| **No Jekyll plugins** | `plugins: []`. The SEO tags, JSON-LD and sitemap are hand-written Liquid, so a local build is identical to the Pages build. |
| **No third-party origin** | Fonts are self-hosted. No CDN, no analytics, no tracker, no embed. The only outbound URLs are links you choose to click. |

## Editing content

Almost everything is data, not markup. Edit a YAML file, commit, push — Pages
rebuilds in about a minute.

| File | Holds |
|---|---|
| [`_config.yml`](_config.yml) | Name, role, tagline, social profiles, nav, SEO defaults |
| [`_data/metrics.yml`](_data/metrics.yml) | The four headline figures in the hero ledger |
| [`_data/experience.yml`](_data/experience.yml) | Roles, dates, highlight bullets, per-role stack tags |
| [`_data/projects.yml`](_data/projects.yml) | Projects and their result readouts |
| [`_data/skills.yml`](_data/skills.yml) | Skill categories (counts are computed) |
| [`_data/education.yml`](_data/education.yml) | Degrees |
| [`_data/certifications.yml`](_data/certifications.yml) | Verified coursework |
| [`resume.pdf`](resume.pdf) | Linked from the hero, the experience section and the footer |

Prose that isn't list-shaped — the About section — lives in
[`_includes/sections/about.html`](_includes/sections/about.html).

Highlight bullets accept inline HTML, which is how the numbers get marked. The
template rewrites `<strong>` to the red-pen `.fig` treatment at build time:

```yaml
highlights:
  - Cut inference cost <strong>60%</strong> by self-hosting open models
```

Two conventions worth knowing before editing `_data/`:

- **Months are abbreviated** (`Mar 2024`, not `March 2024`). They render in a
  176–224px monospace rail; the full forms wrap and leave an orphaned year.
- **`compact: true`** on a role renders its summary and drops its bullets. It
  exists so a thin role doesn't sit next to a six-bullet one looking like
  filler. It's an explicit flag rather than a template heuristic, so a future
  edit can't make content vanish invisibly.

## Local preview

GitHub Pages builds this for you, so this is only needed to see changes before
pushing. Requires Ruby 3.x and nothing else.

```bash
bundle install
bundle exec jekyll serve --livereload
# http://127.0.0.1:4000
```

## Checks that run on push

[`.github/workflows/ci.yml`](.github/workflows/ci.yml) builds the site with the
same `github-pages` gem Pages uses, runs `html-proofer` over the output to verify
every internal link, image, script, anchor and Open Graph tag resolves, and
asserts the original template's attribution has not crept back in. A broken
Liquid tag or a dead anchor fails CI instead of shipping.

External links are checked [monthly](.github/workflows/links.yml) rather than on
push, so a commit never fails because LinkedIn rate-limited the runner.

## Design notes

Two rules in [`assets/css/main.css`](assets/css/main.css) are load-bearing, and
both are stated at the top of that file:

1. **Accent scarcity.** The one accent colour appears in exactly five roles —
   section numerals, links, the `.fig` underline, readout fills, and the focus
   ring. Each additional use looks fine alone; together they'd cost the page its
   authority.
2. **No fills.** Every surface is `--paper`. Structure is carried entirely by
   1px rules, which is why those rules are held to 4.5:1 contrast rather than
   the 3:1 WCAG asks of non-text.

A third rule lives in [`_includes/readout.html`](_includes/readout.html): **no
readout without two real values.** The two projects get result instruments
because `0.9845`-of-`1` and `66→69`-of-`100` are genuinely two numbers. The four
hero metrics deliberately get none — a 26% *gain* has no stated baseline, "30K+
chats" has no denominator, and "7 tenants" has no cap, so any bar would be
inventing the missing half. Fabricated telemetry is the worst available failure
on a page whose argument is that this person keeps systems honest.

## Accessibility & performance

Verified in a real browser at 320–1440px in both themes:

- Zero horizontal overflow at any width; zero WCAG contrast failures. Body text
  clears AAA (17.5:1 light, 16.1:1 dark) and the smallest 11px monospace
  marginalia still clears 7:1.
- Semantic landmarks, one `h1`, no heading-level skips, a skip link, and a
  visible focus ring on every interactive element.
- The theme is a real three-state control — **system / light / dark** — because
  "following the OS" has to be a state you can see and get back to. It's a
  native radio group, so arrow-key navigation and grouping come free. The
  resolved theme is applied before first paint, so there's no flash of the wrong
  colours, and an OS theme change mid-session is honoured while on *system*.
- All motion sits behind `prefers-reduced-motion`, with targeted overrides so
  nothing is left stranded invisible. Content is authored visible; JavaScript
  only ever *adds* the hidden start state.
- 180 KB of fonts across four self-hosted faces (down from 301 KB unsubset — see
  [`assets/fonts/README.md`](assets/fonts/README.md)), two preloaded, with
  metric-adjusted local fallbacks so the swap shifts nothing.

**Printing** produces a properly typeset document of roughly four A4 pages: page
chrome drops out, the key figures survive four-up as real borders rather than
grid-gap backgrounds, dot leaders become dotted rules, and a contact header is
added to page one. It's a supplement to `resume.pdf`, not a replacement — a
strict one-pager would mean dropping the About prose and project descriptions,
which is a content decision rather than a CSS one.
